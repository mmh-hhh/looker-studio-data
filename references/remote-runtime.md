# 跨平台运行与重复任务

这份说明供 agent 使用。业务用户只需要提供链接并在必要时本人登录。

## 最小运行条件

- 支持 macOS、Windows 和 Linux；
- Node.js 是基础运行时；
- Playwright 是唯一外部运行依赖；
- 浏览器自动按 Chrome、Edge、Chromium 的顺序选择；
- AI 环境已经提供 Playwright 时直接复用，不重复安装。

脚本按以下顺序自动发现 Playwright：仓库本地依赖、当前 `NODE_PATH`、Codex workspace bundled runtime。三处都不存在时以 `PLAYWRIGHT_NOT_FOUND` 失败关闭，不尝试静默降级为 DOM 抓取或截图。`doctor` 的 `playwright_source` 可用于确认实际来源。

用户平时使用 Safari、Firefox 或其他浏览器没有关系。skill 使用独立的自动化浏览器状态，不读取用户日常浏览器中的密码。

环境缺少依赖时由 agent 补齐并运行 `doctor`、`self-test`；不要让业务用户照抄安装命令。不同平台的私有运行目录由脚本自动选择，也可以由项目明确指定，不能写死某台机器的绝对路径。

代码和运行数据必须分开：

- skill 目录只放代码和文档；
- profile、登录态、目录、配方和 CSV 放在私有运行目录；
- macOS/Linux 使用 `0700`、`0600`；Windows 使用当前用户专属目录和等效 ACL；
- 所有运行数据排除在 Git、公共制品和普通日志之外。

## 登录方案按结果选择

| 场景 | 最短可靠方案 |
|---|---|
| 本机偶尔下载 | 在本机受支持浏览器中登录并直接导出 |
| 本机重复下载 | 复用同机专用登录状态 |
| 服务器定时任务 | 在目标机器建立并验证登录状态；没有图形界面时使用公司允许的临时远程桌面 |
| 已有登录状态需要迁移 | 通过批准的密钥系统传输，并在目标机器重新验证 |

登录只从 `https://datastudio.google.com/` 开始。已有 Chrome 时优先 Chrome；没有 Chrome 时自动使用 Edge 或 Chromium。用户本人完成账号、密码、MFA、验证码和授权，agent 不读取这些内容。

同一登录状态只能串行使用。Google 登录可能因时间、设备变化或安全策略失效，不能承诺永久有效，也不能用高频访问或降低安全设置强行“保活”。

## 登录状态迁移

登录状态是敏感凭证。可以通过公司批准的 secret 系统传输，但不能进入 Git、聊天附件、普通日志或公共制品。跨机器后必须重新验证；失败就改为在目标机器由用户本人登录，不能循环重试。

即使某个报表暂时可读，也不能据此宣称登录适合长期任务。

## 重复任务验收

必须在目标机器独立成功两次，并且两次都通过权限、筛选、总行数、CSV 结构和 SHA-256 检查。第二次不能依赖人工刷新目录。失败要区分登录过期、报表结构变化和页面请求无法安全复用。

## 什么时候刷新目录

新链接、换报表或筛选、页面结构变化、配方失效、完整性失败时刷新。相同报表和规则正常重复执行，或只改变文件名和保存位置时不刷新。

## 登录过期处理

定时任务做低频健康检查。遇到登录失败、401/403 或 Google 安全挑战时立即停止，用浅显中文通知用户本人重新登录。不要自动填写密码、处理 MFA、破解验证码或高频保活。

只有用户明确确认拥有 BigQuery、Google Sheets 或业务系统原始数据权限时，才讨论正式 API 方案；不能把它当作默认前提。
